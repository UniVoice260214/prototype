# UniVoice Core API — 통합본 결정 문서

세 팀원(서영 / 세희 / 유민)의 Core API 구현을 **PDF 명세 기준**으로 기능별 비교해,
가장 좋은 것을 골라 하나의 통합본으로 합쳤다. 이 문서는 "어느 기능을 누구에게서 가져왔는지"와 그 근거를 기록한다.

> 핵심 결론: **베이스 = 세희** (완성도·운영성이 가장 높음) → 여기에 **서영의 강점을 이식** → 교차검증에서 발견한 **공통 결함을 수정**. 유민은 LiveKit/Blob/Redis/가드가 전부 스텁이라 채택할 고유 기능이 없었다.

---

## 1. 기능별 채택표

| # | 기능 | 채택 | 이유 (왜 이게 제일 나은가) |
|---|------|------|------|
| 1 | 전체 골격(베이스) | **세희** | 마이그레이션·docker-compose·번들 redis/azurite·타입드 이벤트버스·smoke E2E까지 유일하게 "바로 돌아가는" 수준 |
| 2 | env 검증 | **세희** | class-validator 부팅 검증 + `AUTH_DISABLED` 문자열 처리(‘false’ 함정 회피) |
| 3 | DB 스키마/마이그레이션 | **세희** | 손으로 쓴 `InitSchema`(enum·FK·ON DELETE·복합 unique 명확). 서영은 마이그레이션 파일이 0개였음 |
| 4 | 도메인 모델 | **세희** | User+Professor(1:1)+Student 3축 분리, 학생 자체 로그인 가능 |
| 5 | Auth / JWT | **세희** | 교수·학생 로그인 + 학생 signup + JoinToken `type` 강제검증(일반 JWT 오용 차단) |
| 6 | CRUD (학교/학과/과목/교수/학생) | **세희** | 6개 도메인 완비, 교수 생성 시 role 검증, 학생 본인 소유권 체크 |
| 7 | ★ 세션 start/end 오케스트레이션 | **세희** | Redis `multi()`로 config/status/glossary 원자적 prewarm, 멱등 end |
| 8 | LiveKit 어댑터 | **세희** | publish/subscribe 권한 분리 + 미설정 시 graceful 503 |
| 9 | 자료 업로드 + Blob | **세희** | 50MB·MIME 화이트리스트, 컨테이너 자동 생성 |
| 10 | **자료 인덱싱 전달 방식** | **서영** ✅ | Redis **List 큐(`rag:index:queue`)** 가 pub/sub보다 견고 — RAG 워커가 꺼져 있어도 잡이 큐에 남았다가 소비됨. (통합본은 큐 적재 + 라이브 이벤트를 **둘 다** 수행) |
| 11 | **Redis 키 규약 중앙화** | **서영** ✅ | 서영의 `sessions.constants.ts` 패턴 → 통합본 `src/common/redis-keys.ts` 로 채택. 워커와의 키 인터페이스를 한 파일에 명문화 |
| 12 | Glossary + prewarm | **세희** | CRUD + 변경 시 캐시 무효화(`glossary:{courseId}` del) |
| 13 | QR 생성 | **세희** | 전용 QrModule, JoinToken 발급 + dataURL PNG |
| 14 | 공통 레이어(필터/가드/데코레이터) | **세희** | 전역 예외필터 + 전역 JwtAuthGuard/RolesGuard + `@Public`/`@Roles`/`@CurrentUser` |
| 15 | 이벤트/pub-sub | **세희** | 단일 진입점 `EventsService` + `events.types.ts` 타입 계약 + client/subscriber 분리 |
| 16 | smoke E2E 스크립트 | **세희** | 로그인→CRUD→세션→QR→업로드 전 흐름 검증(한글 UTF-8 라운드트립 포함) |
| 17 | 설계 문서 | **서영** | docs 설계 PDF (`UniVoice_CoreAPI_설계.pdf`) |

## 2. 통합 과정에서 수정한 결함 (교차검증으로 발견)

두 분석 에이전트가 **공통으로 지적**했고, 코드리뷰에서 지적당하기 쉬운 항목을 통합하면서 함께 고쳤다.

| 결함 | 어디서 발견 | 통합본 수정 |
|------|------------|------------|
| **passwordHash가 응답 JSON에 노출** | 세희(User/Student 직렬화) | 엔티티 필드에 `@Exclude()` + 전역 `ClassSerializerInterceptor` 적용 → 응답에서 자동 제거 |
| **`materials.indexing.completed` 구독자 없음** → `indexingStatus`가 영원히 pending | 세희(이벤트 타입만 정의) | `MaterialIndexingSubscriber` 추가 — `REDIS_SUBSCRIBER`로 완료 이벤트 수신 시 상태 갱신 |
| **세션 start 중간 실패 시 고아 Session/Room** | 세희·서영 공통 | `start()`에 보상 트랜잭션(try/catch) — 실패 시 Session 삭제 + Room 삭제 + Redis 키 정리 후 재던짐 |
| **자료 삭제 시 Blob 원본 누수** | 세희(DB만 삭제) | `BlobService.deleteByUrl()` 추가, `remove()`에서 Blob까지 best-effort 삭제 |

## 3. AI/RAG 워커가 알아야 할 인터페이스 (통합본 기준)

다른 팀(Python AI 워커 · RAG 워커)과 맞춰야 하는 계약. 정의 위치:
`src/common/redis-keys.ts` (키/큐) + `src/modules/events/events.types.ts` (채널).

| 종류 | 이름 | 용도 | 누가 읽나 |
|------|------|------|-----------|
| Redis key | `session:{id}:config` | 세션 설정 스냅샷(JSON) | AI 워커 |
| Redis key | `session:{id}:status` | `active`/`ended` | AI 워커 |
| Redis key | `glossary:{courseId}` | glossary prewarm(JSON 배열) | AI 워커 |
| Pub/Sub | `sessions.started` / `sessions.ended` | 세션 시작/종료 알림 | AI 워커 |
| Pub/Sub | `materials.indexing.requested` | 인덱싱 라이브 알림 | RAG 워커 |
| **Redis List** | **`rag:index:queue`** | **인덱싱 잡 큐(내구성)** — `BRPOP`으로 소비 | RAG 워커 |
| Pub/Sub | `materials.indexing.completed` | 인덱싱 완료 보고(워커→Core) | Core가 구독 |

## 4. 남은 후속 개선 (통합본에 미반영 — 시간/범위상 보류)

코드리뷰 때 "알고 있다"고 말할 수 있도록 정리. 급하면 추가 가능.

- 리소스 **소유권 검증**: 현재 교수 역할이면 남의 과목/세션도 조작 가능 (role만 보고 professorId 대조 안 함).
- 목록 API **페이지네이션** 부재 (`find()` 전체 반환).
- 실제 `.spec.ts` **단위/e2e 테스트** 미작성 (smoke.ts만 존재).
- 세션 start **중복 호출**(이미 active인 세션 재시작) 가드.
- 운영용 **secret 강제**(JWT_SECRET 기본값 차단), rate-limit/helmet.
